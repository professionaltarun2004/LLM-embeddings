\begin{abstract}
Normalization can be applied to embedding vectors after lookup or to the rows of an embedding table before lookup. This paper asks whether these placements alter embedding geometry, fixed-table representations, or gradients with respect to a shared trainable table. Three controlled experiments use seeded synthetic embeddings and row-wise RMSNorm. In Experiment 0, the mean normalized-to-raw pairwise Euclidean distance ratio was 1.030494, while the maximum absolute cosine-similarity change was \(2.78\times10^{-16}\). In Experiment 1, lookup-then-normalize and normalize-table-then-lookup produced identical fixed-table representations. In Experiment 2, both paths produced the same loss (1.1457136942185433) and numerically equal, nonzero gradients for one deterministic mean-squared-error objective. These results are limited to the tested row-wise operation and synthetic data. No optimizer update, learned embedding, language task, or Transformer was evaluated.
\end{abstract}

\begin{IEEEkeywords}
RMSNorm, token embeddings, embedding geometry, normalization placement, gradient analysis
\end{IEEEkeywords}

\section{Introduction}
Embedding vectors are learned representations of discrete tokens, and normalization is a common operation in neural network computation. Where normalization is applied relative to embedding lookup can therefore matter to the representation delivered to later computation.

This paper asks whether moving a row-wise normalization operation across an embedding lookup changes the resulting vectors or their gradients. The research question is:
\begin{quote}
What happens to the information and geometry of token embeddings when normalization is incorporated into the embedding representation itself, rather than applied after embedding lookup---and does the placement of normalization affect downstream model behavior?
\end{quote}

Two parameterizations must be distinguished. In the tested formulation, raw table \(E\) is the underlying parameter and normalization is part of the forward computation, \(N_{\epsilon}(E)\). A separate formulation would treat the normalized representation \(U\) itself as the optimized variable and use \(U\) in the forward computation. The latter is a different optimization problem and is not tested here.

Normalization placement is not universally innocuous. Prior work has shown that the location of normalization within Transformer blocks can influence gradient behavior and optimization stability \cite{xiong2020layernorm}. RMSNorm itself was proposed as a simpler normalization mechanism based on root mean square statistics \cite{zhang2019rmsnorm}. The Transformer architecture uses residual connections and layer normalization in its sequence-modeling blocks \cite{vaswani2017attention}. Motivated by this broader context, this work isolates a narrower operation: moving row-wise RMSNorm across token-embedding lookup. It evaluates this arrangement under controlled synthetic experiments and makes no claim of novelty.

The investigation proceeds in three steps. Experiment 0 measures what row-wise RMSNorm changes in a seeded synthetic table's geometry. Experiment 1 then tests whether placing that operation before or after lookup changes a fixed-table output. Experiment 2 compares gradients with respect to the same trainable raw table under one controlled loss. Together, the experiments characterize these computations; they do not evaluate optimizer updates or downstream model behavior.

\section{Background and Problem Formulation}
\subsection{Embedding Table and Lookup}
Let the vocabulary contain \(V\) token IDs and let
\begin{equation}
E\in\mathbb{R}^{V\times d}
\label{eq:table}
\end{equation}
be an embedding table with feature dimension \(d\). An ID \(i\in\{0,\ldots,V-1\}\) selects row \(E_{i,:}\). For a sequence \(I=(i_1,\ldots,i_m)\), define the lookup operator \(L_I(E)\in\mathbb{R}^{m\times d}\) by
\begin{equation}
[L_I(E)]_{t,:}=E_{i_t,:},\qquad t=1,\ldots,m.
\label{eq:lookup}
\end{equation}
In Experiments 0--2, \(E\) is generated synthetically by a seeded standard-normal draw. In Experiment 2 it is marked trainable for differentiation, but it is not updated.

\subsection{Row-Wise RMSNorm}
For \(x\in\mathbb{R}^d\), define the implemented normalization as
\begin{equation}
\operatorname{RMS}(x)=\sqrt{\frac{1}{d}\sum_{k=1}^{d}x_k^2},\qquad
N_{\epsilon}(x)=\frac{x}{\max(\operatorname{RMS}(x),\epsilon)}.
\label{eq:rmsnorm}
\end{equation}
RMSNorm was introduced as a computationally simpler alternative to LayerNorm that removes re-centering while retaining re-scaling normalization \cite{zhang2019rmsnorm}. The experiments use \(\epsilon=10^{-8}\), reduce over the feature axis, and use no learned gain or bias. The row-wise extension \(N_{\epsilon,\mathrm{row}}(E)\) applies \(N_{\epsilon}\) independently to each of the \(V\) rows.

\section{Mathematical Formulation}
The two pathways compare lookup followed by normalization with row normalization followed by lookup:
\begin{align}
Y_A(E,I)&=N_{\epsilon,\mathrm{row}}\!\left(L_I(E)\right), &&\text{(lookup, then normalize)},\label{eq:patha}\\
Y_B(E,I)&=L_I\!\left(N_{\epsilon,\mathrm{row}}(E)\right), &&\text{(normalize, then lookup)}.\label{eq:pathb}
\end{align}
By definition, each normalized table row satisfies
\begin{equation}
[N_{\epsilon,\mathrm{row}}(E)]_{i,:}=N_{\epsilon}(E_{i,:}).
\label{eq:rowwise}
\end{equation}
Consequently, for every position \(t\),
\begin{equation}
[Y_A(E,I)]_{t,:}=N_{\epsilon}(E_{i_t,:})=[Y_B(E,I)]_{t,:},
\label{eq:identity}
\end{equation}
and hence \(Y_A(E,I)=Y_B(E,I)\). Lookup selects rows, while the normalization acts independently on each selected row; selection and this row-local operation therefore commute. This identity is specific to the same operation applied independently to rows and does not cover normalization that mixes statistics across rows or a changed parameterization.

In particular, optimizing raw \(E\) while computing \(N_{\epsilon}(E)\) is distinct from optimizing a normalized representation \(U\) directly. Experiments 0--2 retain raw \(E\) as the underlying parameter.

\section{Experimental Methodology}
\subsection{Controls}
Experiments 0 and 1 use seed 1729, vocabulary size 128, and dimension 32. Experiment 2 uses the same seeded initialization methodology and the same underlying tensor in both paths. All experiments use the same row-wise RMSNorm convention and epsilon. Experiment 1 uses token IDs 0--127; Experiment 2 uses \([3,17,42,91]\). No external corpus, pretrained embedding, optimizer, or Transformer is used.

\subsection{Measurements}
Experiment 0 evaluates all \(128\cdot127/2=8{,}128\) unique row pairs. Experiment 1 compares corresponding outputs and their pairwise geometry. Experiment 2 compares representations, scalar losses, and full gradients with respect to \(E\). Relative differences omit reference elements with magnitude at most \(10^{-12}\). Numerical equality checks use \(\mathrm{atol}=10^{-12}\) and \(\mathrm{rtol}=10^{-12}\).

\section{Experiment 2: Trainable Embedding Gradients}
\subsection{Question}
Experiment 1 established fixed-table forward equality. Does the equivalence also appear in gradients with respect to the same trainable raw table?

\subsection{Setup}
Both paths use one shared \(128\times32\) PyTorch float64 tensor initialized with seed 1729 and token IDs \([3,17,42,91]\). An assertion checks that the conceptual table references are the same object and have exactly equal values. Path A looks up the selected rows before normalization; Path B normalizes the table rows before lookup. Both use the same downstream operation, target, loss, and equality tolerance. No optimizer or parameter update is performed.

The downstream mapping is the identity. The target \(T\) is a deterministic float64 linspace from \(-0.5\) to \(0.5\), reshaped to \(4\times32\). For a representation \(Y\), the scalar loss is
\begin{equation}
\mathcal{L}(Y)=\operatorname{mean}\!\left((Y-T)^2\right).
\label{eq:loss}
\end{equation}
Both paths use the same target and objective; no additional trainable parameter is introduced.

\section{Discussion and Open Questions}
\subsection{What Does RMSNorm Change?}
On the synthetic matrix, RMSNorm changed row magnitudes and pairwise Euclidean distances, while pairwise cosine similarities were preserved to numerical precision. This describes the measured geometry; Experiment 0 did not measure information content or learned embedding behavior.

\subsection{Does Moving Normalization Across Lookup Change the Computation?}
For a row-wise normalization function applied independently to each embedding row, moving that operation across a row-selection lookup is algebraically equivalent when the underlying trainable parameter remains the same raw embedding table \(E\). Experiments 1 and 2 provide numerical checks of fixed-table outputs and, for one controlled objective, gradients with respect to \(E\). The experiments do not show that normalization placement never matters.

Prior work has shown that layer-normalization location within Transformer blocks can affect gradient behavior and warm-up requirements \cite{xiong2020layernorm}. That work studies normalization inside Transformer architectures, not the embedding-lookup identity evaluated here. The present result is limited to the specific row-wise operation and parameterization defined above.

\subsection{What Remains Unresolved?}
\textbf{Parameterization A:} raw embedding table \(E\) is optimized, and the forward computation uses \(N_{\epsilon}(E)\).

\textbf{Parameterization B:} the normalized representation \(U\) itself is the optimized variable, and the forward computation uses \(U\).

These are not the same optimization problem. Parameterization B has not been experimentally tested; no optimizer step was taken in Experiments 0--2. This distinction motivates the next stage of the investigation.

\section{Limitations}
The evidence is deliberately narrow:
\begin{itemize}
\item Embeddings are synthetic; no pretrained model, corpus, or language task was used.
\item No Transformer, downstream task, optimizer step, or learned representation was evaluated.
\item Experiment 2 uses one deterministic target, one MSE objective, one token subset, and float64 only.
\item No comparison with other normalization methods or normalization that mixes statistics across tokens was performed.
\item No direct optimization of normalized embeddings was tested.
\item Experiment 0 does not measure information content, and none of the experiments establishes behavior for learned language-model embeddings.
\end{itemize}

\section{Conclusion}
For the tested synthetic matrix, row-wise RMSNorm changed vector magnitudes and pairwise Euclidean distances while leaving cosine similarities unchanged to numerical precision. For this row-local operation, normalization before lookup and after lookup are algebraically identical arrangements of the same table \(E\). The experiments found identical fixed-table outputs and, for one controlled nonzero-gradient loss, numerically equal gradients with respect to \(E\). Direct optimization of a normalized representation, optimizer behavior, and downstream model effects remain untested.
